# #37 云端识别用量与每月提醒：实现与验收状态

本任务属于 [#26](https://github.com/xiaolin624/listen/issues/26)。**实现和离线验证已完成；真实账号的费用核对、真实账单和日常 100 元提醒的真实触发仍需要付费调用条件，因此本票不作为真实计费证据。**

## 用户能看到什么

云端试用时，结果面板的状态区在厂商/型号/地域（`backend`）之后新增「云端用量」区块：

1. **覆盖声明与次数**：仅统计本工具发出的识别请求，不含同一云账号的其他应用或套餐；累计请求次数、其中重试（自动重建或重复请求）的次数，并分别列出已确认、保守估算和未知的次数。重试会再次计费，不承诺去重免费。
2. **金额与计费维度**：`累计费用估计 = 已确认 + 保守预留`；已确认用量给出厂商最终上报的输入/输出 tokens。未知请求明确写「不按 0 元计」。
3. **本月与两道线**：本月（UTC）合计、每月 100 元提醒线和首轮 50 元试用上限。提醒线只提醒，不会停用功能、取消录音、购买套餐或提高额度；50 元是硬上限，单独生效。
4. **旧记录**：无法确定月份的旧账本记录单列，计入累计、不计入本月。

本月合计接近每月 100 元提醒线（达到 90 元，即提醒线的 90%）时，应用另外产生一次 `Notice::UsageReminder`（面板与 `status.txt` 的 `notice=` 可见），文案明确说明「这只是提醒」以及采集、识别与安全回填照常继续。应用只在账本刷新时产生该提示，采集过程中不检查任何预算或提醒条件，因此提醒不可能中断录音。

`status.txt` 追加以下键（原有键不变）：

```
usage_available=0|1
usage_unreadable=0|1
usage_requests=
usage_confirmed_nanoyuan=
usage_estimated_nanoyuan=
usage_unknown_requests=
usage_retried_segments=
usage_undated_requests=
usage_month_nanoyuan=
usage_month_reminder=0|1
usage_month_reminder_nanoyuan=100000000000
usage_trial_cap_nanoyuan=
```

## 数据从哪来、边界在哪

- **唯一账本**：仍是 `%LOCALAPPDATA%\Listen\cloud-trial\ledger.json`（#29）。没有第二份用量文件，月度累计由同一账本的请求记录派生，所以重启、换运行目录、换型号都不会归零。
- **增量字段**：每条 `Attempt` 新增可选 `requested_at_utc`（Unix 秒）。旧账本没有该字段仍按原版本加载；这些记录只进累计，标为「无法确定月份」，不会被塞进本月。`deny_unknown_fields` 与 `version=1`、`cap_nanoyuan=TRIAL_CAP_NANOYUAN` 的校验均未放宽。
- **已确认 / 保守 / 未知**：已确认 = `final_usage` 且按已核实价格源计价；保守 = 未取得最终用量的整笔预留；未知 = 未取得最终用量，或最终扣款未核实（FreeOnly 记录现金为 0 但用量与实扣未知）。未知数不会因为其中某笔现金为 0 而显示成「没有花费」。
- **账本不可读**：`UsageSummary.unreadable` 为真，面板写「无法读取…不能当作 0 元」，并拒绝新的付费请求。汇总不会把读不到的账本显示成 0。
- **月份**：按 UTC 自然月归属，面板明确写「UTC」。本仓库没有时区数据库，也不引入新依赖；提醒线是软提醒，允许该边界差异，从不当作账单周期。
- **提醒触发点**：本月已记录费用（已确认 + 保守）**达到 90 元（100 元提醒线的 90%）**时触发，属于“接近即提醒”，不是只在越过 100 元后才提醒。100 元仍是提醒线的名称与 `usage_month_reminder_nanoyuan=100000000000` 的稳定值；阈值是 `UsageSummary::REMINDER_THRESHOLD_NANOYUAN`，只影响提示，不涉及账本、准入或 50 元上限。
- **读取时机（重要）**：只在「构造应用」「启动在产生 worker 之前就失败」「会话已经结束/失败、worker 已返回」三处读取账本。云端会话进行中**不读**账本，因为账本的排他锁同时是付费请求的准入锁：界面侧抢先读会让 worker 的下一次预留拿到 `LedgerBusy` 并阻塞本可继续的采集。代价是采集进行中看到的是上一次刷新结果；结束时刷新为最终值。
- **50 元硬上限不变**：`reserve` 的准入、预留和冻结逻辑一行未改；本月提醒从不参与准入。测试用一个「本月 > 100 元且已用 > 50 元」的账本同时证明：提醒可见、启动仍被 50 元上限拒绝。

## 测试覆盖（应用 Interface）

`app/listen/tests/usage_ledger.rs`，全部通过 `Application::dispatch` / `poll` / `snapshot` 断言：

- 构造后与采集期间都能看到适配器报告的累计用量；
- 真实云适配器完成一次识别后，最终用量按已核实价格计为已确认费用，本月合计与生命周期一致；
- 旧版本账本（含重试记录、缺失最终用量、FreeOnly 未知实扣）仍能加载：重试段数、保守预留、未知次数、无法定月的历史都可见，重启后不变；
- 跨月：上月与无日期记录计入累计但不计入本月，本月只统计本月，重启后月度累计保留；
- 接近 90 元提醒阈值和达到 100 元提醒线都不拒绝启动、不中断采集，结果照常保存与交付；
- 本月 > 100 元、已用 > 50 元时提醒可见，但启动仍由 50 元上限拒绝，账本上限与已用金额均未改变；
- 账本不可读时显示未知并拒绝新的付费请求，而不是 0 元；
- 快照（`status.txt`/`panel.txt` 的唯一来源）与账本都不包含 API Key、`Bearer` 或 `Authorization`。

面板与 `status.txt` 的呈现由 `panel.rs` 的单元测试直接覆盖（确认/保守/未知分列、重试计费、覆盖声明、提醒文案、账本不可读不显示 0）。

## 仍未完成（保持 #37 开放的真实条件）

- 真实账号下核对一次识别请求的最终用量与实际账单，确认未知项可以结清；需要本机凭据与付费调用，计入 50 元首轮预算。
- 日常模式下真实触发提醒：当前 50 元首轮硬上限使「本工具本月累计」在试用阶段无法到 90 元；提醒逻辑与显示已实现并用受控账本验证，真实触发要等日常预算策略（#40）落地。
- 提醒在 100 元线的 90%（90 元）触发，属于“接近即提醒”；100 元只是这条提醒线的名称，不再作为触发条件，也不参与任何预算决策。
