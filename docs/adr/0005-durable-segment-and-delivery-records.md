# 多段与交付状态用带版本的本地记录持久化

状态：accepted（2026-11-21）

多段采集、断网补处理和重启恢复需要跨进程记住“哪一段、到哪一步、文字在哪里、是否写过目标”。这些事实不能用进程内状态或日志近似，也不能让一次崩溃把未取结果变成“没发生过”。决定：运行目录使用两份带版本的原子替换 JSON 记录。`segments.json` 保存采集序号、会话目录、段状态、文字文件名、逐段费用、捕获时术语快照和当前结果序号；`segment-NNNNNNNN.txt` 保存每段完整文字，先写文字再更新索引。`delivery.json` 保存每段交付状态（`pending`、`started`、`appended`、`fallback`、`uncertain`）与写前/写后草稿，写目标前先落盘 `started`，读回确认后才记 `appended`。未知版本或损坏的记录只报告降级并保持原样，绝不静默重写或猜测状态。

## 后果

- 恢复只读不删：完整文字可读时释放音频，否则保留全部录音；待取结果不按日期过期。重启后没有旧窗口/输入框句柄，所以恢复结果一律留在面板，绝不自动回填。
- 已解决（`appended`/`fallback`）的交付历史按条数与字节有界修剪；`pending`/`started`/`uncertain` 永不修剪，因为它们是防止重复写入的安全标记。缺链只会让迟到结果更保守地留在面板，并在原因中说明是历史被修剪，而不是声称用户改过目标文本。
- 目标写入仍受单写入者与完整读回确认约束；`started`/`uncertain` 是终态，重复事件、重复停止和重复 poll 都不能再写一次。磁盘记录只用于证明/保守判断，从不被当作“已发送”或“已成功”的替代证据。
- `segments.json` 与 `delivery.json` 的版本提升是兼容性决策：旧版本可读时保持原样，新字段用可选/默认值追加。
