# 耳机音频转写：需求访谈记录

本文记录已确认的需求和待明确的问题，尚非实施规格。

## 已确认

- 第一版用于 Windows，声音由同一台电脑播放到用户所用的耳机。
- 采集当前耳机播放的全部音频，转写其中的语音，不按来源应用筛选。会议、聊天、浏览器等应用均属于需求范围，用户无需选择声音来源应用。
- 第一版不主动采集本人的麦克风声音；若某段语音已经通过耳机播放，则属于耳机音频的采集范围。
- 工具常驻后台，通过全局快捷键切换开始采集和停止采集；具体按键待定。
- 文字用于填入大模型或 agent 的输入框，用户不需要字幕展示。
- 用户先点击或双击目标输入框，再按全局快捷键开始采集；工具为本次采集记住该目标，切换窗口后仍向原目标输出。
- 产品面向用户指定的输入框，不要求用户选择或理解输入框所属应用类型。已知常见场景包括 Codex 桌面端及浏览器中的插件输入框。
- 文字追加到原有内容末尾，保留原内容；填入后由用户手动发送。
- 没有目标输入框或自动填入失败时，显示工具自己的备用文本框，供用户复制粘贴。
- 语言以普通话为主，兼顾夹杂的英文单词或技术词。
- 使用本地语音识别。用户期待速度快，实际等待时间仍需本机验证。
- 单次采集不设固定时长上限，不能把任意设定的几分钟当作产品限制。
- 优先追求高性能，考虑 Rust 等语言；具体识别引擎和技术方案尚未选定。
- 第一版不自动保存会议历史，保留当前结果供复制；临时音频转写成功后清理，转写失败时保留供重试。

## 后续需原型验证

- 用户选定输入框后，切换窗口再回填的可靠性，以及对 Codex 桌面端、浏览器插件输入框等不同实现的适配。
- 按耳机播放设备采集音频时，对不同来源应用、实际耳机及设备切换的兼容性。

## 已核实的技术条件

- Windows 支持捕获播放到输出设备的音频；腾讯会议、飞书与具体耳机组合仍需实测。
- 本机具备 i5-11400H、16 GiB 内存及 RTX 3050 Laptop GPU（4 GiB 专用显存）。
- 本地识别的速度受硬件、模型和音频长度影响；已有初步 CPU / CUDA 本机基准，正式端到端耗时和真实会议表现仍需验证，详见验证报告。
- Windows 的播放设备级音频采集可以获取该设备上的混合声音，符合本项目采集耳机全部音频的需求；实际耳机及音频路由仍需验证。
- Windows 可获取并引用当前输入控件，但控件可能失效，各应用提供的自动写入能力也不同；用户指定目标不等于自动写入已获得兼容性保证。
