# T6：识别失败后重试及临时音频生命周期

## Parent

[规格 Issue #1](https://github.com/xiaolin624/listen/issues/1)

## What to build

一次采集识别失败后，用户能从清楚的错误状态使用本次临时音频在本地重试，无需重新播放原发言。重试成功仍沿本次既定的结果交付规则输出，并清理成功处理后的音频；用户也能明确清理失败音频。

沿用既有备用文本框即可完成本任务验收。重试是识别失败的恢复流程，不能把“写入未确认”当作再次自动追加同一文本的理由。

## Acceptance criteria

- [ ] 模型或推理后端失败时，保留本次已采集音频，显示可理解的失败状态和本地重试操作。
- [ ] 修复本地可用条件后重试，使用同一份音频得到结果；不要求重放发言，不静默改用云端服务。
- [ ] 重试仍与原采集的目标对应；没有有效原目标时交付备用文本框，不能把结果误投给重试时当前焦点下的其他输入框。
- [ ] 重试失败仍保留可重试音频；成功后清理相应临时音频，而当前转写结果仍可查看和复制。
- [ ] 用户明确清理失败音频后，状态相应更新，不继续对不存在的音频执行无效重试。
- [ ] 不自动生成会议历史、长期归档或云端副本；当前结果和失败重试数据不会与其他采集混淆。
- [ ] 写入未确认时不因重试操作重复追加；从完整流程入口覆盖首次失败、连续失败、恢复成功和用户清理。

## Blocked by

- T1：需要现有采集结果、基础失败反馈和备用文本框。
