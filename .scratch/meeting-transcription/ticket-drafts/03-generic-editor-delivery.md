# T3：通用桌面及网页编辑区的自动回填

## Parent

[规格 Issue #1](https://github.com/xiaolin624/listen/issues/1)

## What to build

扩展完整采集流程中的目标输出能力，使用户指定桌面应用、浏览器或插件编辑区后，工具自行适配可用的追加方式。用户操作始终是选择输入框、开始、停止，不需要先声明应用或控件类型。

以 Codex 桌面端和网页/插件编辑区作为实际验证样例，形成可确认写入的通用能力和明确的不可写回退，而非按应用清单分流的用户操作。

## Acceptance criteria

- [ ] 至少在 Codex 桌面端输入框、浏览器普通编辑框及一个网页/插件富文本编辑区运行完整采集到输出流程，并分别记录实测结果和限制。
- [ ] 对具备可用且可确认写入能力的编辑区实现自动追加；不能仅因未完成适配就把整类编辑区归为不可写。
- [ ] 用户无需选择应用类型或声音来源应用；目标仍在开始时由用户明确选定，切窗不改变目标。
- [ ] 追加保留最新原文、已有编辑和完整中英文多行结果；任何换行、焦点恢复或输入方式均不自动发送消息。
- [ ] 恢复目标过程中确认身份与可编辑状态，不能向同名、重建或当前焦点下的另一个控件误写。
- [ ] 对平台限制、目标无可靠写入/确认能力等情况，保留完整结果到备用文本框并说明结果状态，不盲目重复投递。
- [ ] 给出可复核的实际环境证据，并用完整流程入口覆盖可写和不可确认的分支；原生实验成功不代替真实编辑器验证。

## Blocked by
