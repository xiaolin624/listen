# T5：长时间后台分段转写与完整停止收尾

## Parent

[规格 Issue #1](https://github.com/xiaolin624/listen/issues/1)

## What to build

用户可持续采集耳机音频，工具在后台持续处理，并在停止后交付按顺序合并的完整转写文本。采集过程不展示字幕，不设置固定分钟数上限，也不把整段音频一直堆在内存或全部留到停止后才处理。

本任务可使用既有备用文本框完成端到端验收；若自动回填已集成，则沿用同一结果交付入口。资源不足或识别积压必须可见，不能通过静默丢音维持表面上的正常状态。

## Acceptance criteria

- [ ] 长时间采集过程中持续进行本地识别；音频缓存和任务队列受控，采集不被耗时推理阻塞。
- [ ] 跨段词句、重叠区域、短于一段即停止和最终不足一段的内容都得到正确收尾；以确定性样本验证顺序正确、边界不重复和不遗漏。
- [ ] 单次采集没有产品预设时长截断。至少完成一次 60 分钟连续验证；60 分钟只是测试样例，不是产品上限。
- [ ] 连续验证记录音频缓存、积压、内存和停止后收尾时间，证明未按总时长无界积累完整音频或任务队列。
- [ ] 模拟推理变慢、队列压力和磁盘等资源不足，明确反馈积压或中断，保留已接收内容或可恢复结果，不静默丢弃音频。
- [ ] 停止后结果通过当前交付方式完整可见；重复停止不产生重复收尾或重复结果，采集期间仍没有字幕输出。
- [ ] 通过已确认的完整使用流程入口验证长会话、短会话和受压场景，并如实报告实际测量及尚未覆盖的边界。
