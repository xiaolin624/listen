# T4：写入异常、超长结果和重复操作下保全结果

## Parent

[规格 Issue #1](https://github.com/xiaolin624/listen/issues/1)

## What to build

用户停止采集后，即使目标不可用或交付结果无法确认，也能得到完整、可复制的当前转写文本，并知道是否需要先检查原输入框。重复快捷键或停止操作不能造成多份追加。

通过完整使用流程交付异常行为，覆盖目标销毁、重建、只读、禁用、容量限制和可能部分写入等情况。正常目标追加及备用文本框已经存在，本任务补齐这些场景的结果保全和明确反馈。

## Acceptance criteria

- [ ] 目标关闭、被重建、只读或禁用时，不向替代控件输出，完整结果进入备用文本框。
- [ ] 目标字数上限或其他容量限制导致截断时，不能把截断结果报告为完整成功；备用文本框保留完整转写文本。
- [ ] 写后内容不符、超时、并发变化或可能部分写入时，明确表示写入未确认，并提示用户检查原框；不自动重试或自动回滚原文。
- [ ] 重复停止、快捷键按住产生的重复事件、处理中收到操作时，状态明确，同一段结果不会重复输出，也不会与其他采集的目标或结果混淆。
- [ ] 任何失败分支均不自动发送，不修改非目标输入框；备用文本仍可正常查看和复制。
- [ ] 从同一应用开始/停止入口，用可控目标故障验证上述行为，并补充可复现的原生控件集成场景。
