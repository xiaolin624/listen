# T9：硬件加速、准备状态与端到端延迟优化

## Parent

[规格 Issue #1](https://github.com/xiaolin624/listen/issues/1)

## What to build

用户启动工具后能正确知道模型是否可用；在可用状态开始采集，停止后尽快得到完整结果。结合持续处理路径和固定识别质量基线，评估本机 CPU / GPU、模型复用、预加载和预热，采用实测有效的本地策略。

现有 26.460 秒样本中，CPU 约 2.7 秒，CUDA 首次约 12.8 秒、后续约 1.2 秒，均为进程基准。本任务测量正式使用路径，不能把旧数字当作产品延迟承诺，也不能仅靠编程语言名称或降低识别质量宣称优化完成。

## Acceptance criteria

- [ ] 首次模型准备、就绪、采集中和处理中状态准确可见；没有实际具备条件时不显示虚假的就绪或已采集状态。
- [ ] 评估并接入实测有效的模型复用、准备或加速策略；正常使用不显示字幕、不抢走已选目标焦点。
- [ ] 使用 T8（#9） 的同一质量样本、模型/配置或有明确可比性的配置，记录优化前后首次使用与后续使用的耗时和识别结果。
- [ ] 测量从停止操作到文本出现在原目标或备用文本框的完整延迟，并区分模型准备、后台积压与结果交付的影响。
- [ ] 在 T5（#6） 的持续处理路径上测量长时间采集的收尾时间、内存、GPU 与显存，以及同时开会时的流畅度，不能只给独立命令行推理跑分。
- [ ] GPU 或本地加速不可用时，在可用本地后端与明确失败反馈之间正确处理；不静默切云，不丢失待处理音频。
- [ ] 提供可复核的本机配置、样本、首次/后续测量和质量对照；不新增未获约定的固定延迟 SLA 或时长上限。
